# HourOps public marketing redesign

## Original problem statement

Perform a major, intentionally art-directed UI/UX redesign of the existing HourOps marketing landing, not a light polish. HourOps is a workforce time-operations platform bridging Employees → Managers → Projects → Payroll. Preserve authenticated pages, auth/onboarding and CTA behavior; inspect existing source/logo/favicon/tokens first. Use navy/blue/cyan original identity, connected LOG/SUBMIT/REVIEW/APPROVE/REPORT story, realistic HTML product surfaces, stronger timesheet/reporting/payroll-ready stories, people context, Excel import, and isolated branded workspaces. No fake social proof or payroll-processing claims. Provide accessible, responsive, restrained motion and run typecheck/lint/build, desktop/mobile checks, design/file-change summary.

User confirmed proceed with defaults and `feature/landing-page-redesign` only on https://github.com/KingCarni/XQATimesheets; never modify `main` or `integration/current-mvp`. Additional explicit preference: high-craft editorial art direction, masked hero reveal, numbered chapters, one slow marquee, framer-motion, lenis, and subtle hero parallax. Supplied actual timesheet/report screenshots.

## Architecture decisions

- Initial /app was CRA + FastAPI + Mongo template, not the user's repository.
- Cloned canonical Next.js 16.3.1 / React 19.2.8 / TS / Prisma / Auth.js source into `/app/hourops`, on user's requested branch, starting at e728324f9c85e4b85a1dea86c08264340aa1c668. No remote pushes/commits. Root /app also switched to feature/landing-page-redesign before any edits.
- All original business/auth/database code untouched. Only app/page.tsx presentation delegates to LandingPage, preserving its existing auth/tenant routing and server demo action.
- CSS scoped to `.ho-site`; original global stylesheet/root layout/assets intact.
- Marketing components in `/app/hourops/components/marketing`. Framer Motion + Lenis only added runtime dependencies. Existing npm lock synchronized narrowly; Yarn lock added.
- /app/frontend is isolated CRA preview generated by `/app/scripts/sync-marketing-preview.cjs` from canonical TSX, using adapters for next/link and next/image. Do not edit generated JS directly; edit canonical TSX/CSS then run sync.
- Preview `/signup` and `/login` explain marketing-only scope; they are NOT replacement auth. Original source keeps real /signup /login routes and live server demo action.
- No backend alterations, integrations, tenant queries or persistence needed. Product interactions use explicitly illustrative local presentation data; no API mocks.
